# バーチャルハンド錯覚：机上実験と固有受容感覚ドリフト

`Runtime/VirtualHand` と `Editor/VirtualHand` は、固定した仮想右手への視触覚刺激、配置オフセット、溶解、任意のESP32振動、前後の位置判断を扱います。FPSArmの運動追従とは別の実験系です。実験者が右コントローラーを筆に固定して実手をなで、同じ軌跡を仮想手へ対応付けます。

## 起動と配置

URPプロジェクトで `Tools > Avatar Experiments > Virtual Hand > Create PC experiment scene` または `Create VR experiment scene`。生成先は `Assets/VirtualHandExperiments`（既存の場合は別名）です。既存シーン、Build Settings、XR設定は変更しません。実験者用の `Experiment operator` ウィンドウを開きます。サンプルの手は独自生成の簡略形状で、研究用ハンドの妥当性を保証するモデルではありません。

この版の実験者パネルはUnity Editor用です。PCプレビュー／EditorでのPCVR実験を対象とし、Quest単体APK用の実験者UIは含みません。PCシーンのPlay中だけXR自動起動を一時停止し、Play終了時に元に戻します。VRシーンでは通常のXR設定を使用します。

実験に用いる手は、自分が使用権を持つモデルのMeshRenderer/SkinnedMeshRendererを選び `Create ... from selected hand renderer` で静止メッシュへ変換できます。対象は単一マテリアルの手・前腕メッシュ。事前にメートル単位、指が+Z、机面がXZになるよう姿勢とサイズを整えてください。生成した3つの位置合わせ点と `Drift target` を対象モデルの解剖学的位置へ合わせます。全身メッシュから手だけを自動切り出す処理ではありません。

`Viscous` の標準材質はURP Lit。`MeltingTest` と `MeltShaderUrp` の材質スロットは任意です。元プロジェクトで使用した第三者シェーダー・皮膚テクスチャ・fp_male_handは配布しません。利用者が別途導入して割り当てます。3方式とも共通のCPU形状変形を使用し、第三者材質の変形を重ねないプロパティ設定を行います。未割当の材質は実行できません。

VRは導入先でOpenXRを有効にし、床原点を使います。Meta Link/SteamVR等のランタイムは導入先で選択します。Participant Cameraの `Physical Table Height` を実机に合わせます。生成シーンにはコントローラーの可視モデルを置きません。

## 実験前の登録

1. Playし、必要な時だけ `Show calibration markers only` をON。これは参加者への本刺激ではなくセットアップ用です。参加者が同期刺激を経験しない配置確認手順を実験計画に定めてください。本試行中はこのプレビューを禁止します。
2. 筆先を一点に固定してピボット計測（3秒、複数軸回転）。または実測したコントローラー局所オフセットを入力して確定。
3. 実手と仮想手の対応する3点を登録。最大対応誤差が設定値（初期10 mm）を超える場合は不合格です。閾値は装置と研究目的に合わせて事前に決めます。自動的に手を伸縮しません。
4. **独立した点でも筆先と表示位置を照合**。その後、実際の右人差し指先へ筆先を置いて `Capture REAL drift target`。この点は正解参照として記録し、参加者には表示しません。別の解剖学的対象を使う場合はtargetLabelと仮想側のtargetも揃えます。
5. 指示法では左コントローラーのどこを指示点とするか決め、既知の物理点でtip offsetを照合・確定します。対象の右手へ直接触れて位置を知る課題にはしません。必要なら手の下の面に指し示すなど、教示・装置配置を固定します。
6. 実手の遮蔽・机と腕の位置・使用する筆・刺激範囲と速度・振動子の装着位置を確認し、セットアップ確認欄をチェックします。筆先の追跡は接触や圧力の計測ではありません。

## オフセットと同期／非同期

3点登録による**中立位置合わせ**と、条件ごとの**表示変位**は分離しています。条件の `handOffset` は中立手フレームのメートル単位（X横、Y高さ、Z指方向）、`handYaw` は机面内の角度です。指定変位は基準計測前に適用し、その試行中は固定します。

筆先の実座標 → キャリブレーションした手の局所座標 → オフセット後の仮想手、の順で変換します。非同期条件では実座標履歴に時間遅延を適用してから同じ空間変換を行います。オフセットを加えた後に再度位置合わせして変位を消してしまう構造ではありません。

実手は動かしません。意図しない仮想手の移動、原点移動・再センタリングは無効化します。実手そのものの移動は筆の追跡だけでは検出できないため実験者確認が必要です。動いた場合は試行を中止し、再登録して新しいrunにします。

## ドリフト計測の4方式

以下は**論文を参照したVRへの実装**であり、装置・条件・質問紙を含む完全追試ではありません。

| 方法 | 元の手法の参照 | 本実装 |
|---|---|---|
| InvisibleControllerPointing | [Slater et al., 2008, Towards a digital body](https://www.frontiersin.org/journals/human-neuroscience/articles/10.3389/neuro.09.006.2008/full)：非刺激側の手による、刺激前後の感じられた手位置の指示。 | 左コントローラーの非表示tipで回答。物理マーカーの代わりに追跡座標を記録し、既定3反復の平均。対象点は設定可能。 |
| MarkerAdjustment | [Rohde et al., 2011, Experiment 2](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0021659)：暗視野内の点を感じられた指位置へ調整し、3反復の平均を使用。開始位置はランダム。 | HMD内の点を左スティック／矢印キーで移動。Enter／左トリガーで確定。範囲は設定可能、既定±20 cm。 |
| AlternatingStaircase | [Rohde et al., 2011, Experiment 1](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0021659)：点が実指より左か右かの二択、4 cmと1 cmの2系列を交互に更新。 | 同じステップの二系列。既定80回答。末尾の反転点による位置推定と両系列の生データを保存。この停止・推定規則は本実装の設定で、原論文の手順全体の複製ではありません。反転不足・範囲到達は無効。 |
| RandomizedRuler | [Temporal dynamics of the Rubber Hand Illusion, 2023](https://www.nature.com/articles/s41598-023-33747-2)：隠した実指の位置を定規上の番号で口頭回答。定規は判断ごとにずらす。 | VR定規の位置と番号原点を変え、実験者が回答番号を入力。番号を物理座標へ戻して保存。既定反復数は本実装の設定。 |

初期状態はMarkerAdjustmentです。方式はrun開始時に固定され、前後で同じ方式・対象点・軸を使います。`axisInTrackingSpace` の初期値は床原点の+X。左右二択を使う場合は、この軸が参加者の右方向と一致することを確認してください。任意の斜め軸なら教示も対応させます。

同じ `Virtual Hand` メニュー内の `Measurement presets` から4方式を選べます。条件・オフセット・提示時間を変えずに測定方式を切り替えます。`Condition presets` は別の操作で条件表を置き換えます。実験者パネルの `Protocol, conditions, offsets and measurement method` で反復数や条件ごとの変位を編集できます。

測定中は通常シーンのRendererとCanvasを非表示にし、背景を黒にします。指示法は回答位置も非表示。調整法・二択法は点だけ、定規法は定規を表示します。正解点、前の回答、平均、ドリフト量は参加者へ表示しません。外部のパススルー・別カメラ・OSオーバーレイは本機能の制御外です。

原論文では測定による誘導中断が結果に影響することも報告されています。本実装は既定では誘導を途中で中断せず、基準と刺激系列終了後に測定します。方法を切り替えた結果を同一の測定としてまとめないでください。

## 算出と保存

共通のXR追跡空間で、測定軸をa、実対象点をr、回答をpとすると位置誤差は `(p-r)・a`。ドリフトは**事後平均 − 基準平均**で、単位はmです。cmへは100倍、mmへは1000倍します。

- 指示法は3D回答と3Dの前後差も保存します。
- 定規法は各回答の番号、番号原点、定規の物理的なずれを保存し、回答座標へ変換した計算を再現できます。独立点の照合誤差と3点登録誤差も試行ごとに記録します。
- `towardVirtualMetres` は変位した仮想対象へ近づく側を正にします。一次元課題では仮想変位の測定軸成分の符号で計算。成分がほぼゼロなら方向付き指標は未定義としてCSVを空欄にします。
- 二択法は細かい系列の末尾反転位置の平均を採用し、粗い系列の推定、反転回数、範囲到達、全判断を併記します。収束していない値を有効なドリフトにしません。
- 位置ドリフトだけから所有感成立を断定しません。所有感・触覚位置・触覚因果の項目と、溶解・軟らかさ・広がりの探索的項目を別々に保存します。付属の教示・質問文は翻案であり、検証済みの日本語尺度ではありません。

参加者画面の教示・質問は英語です。質問の実際の文面・言語・評定尺度をrunデータにも保存します。対象集団に合わせた訳と尺度の選択は、収集前に実験計画として固定してください。

## 試行の流れ

セットアップ → 基準計測 → 実験者の開始操作 → 準備／誘導／溶解または同時間の非溶解提示／観察 → 事後計測 → 質問 → 休憩 → 実手の位置確認 → 次条件。

練習runは別に開始し `practice=true`。順序はListed、seed固定シャッフル、参加者に割り当てた行による循環順序から選択できます。循環順序は位置の均衡用で、全ての持越し効果を均衡化するWilliamsデザインではありません。反復数、休憩時間、条件表を開始時に複製して固定します。無効試行を勝手に置き換えたり順番を変更したりしません。

初期条件は同期／0.5秒遅延、+17 cm横変位、120秒誘導、溶解なし・振動なしのパイロット設定です。0.1秒の介入区間を置いています。論文の非同期刺激には空間的な不一致等も含まれるため、この固定時間遅延は同一条件の再現とは呼びません。溶解比較では `enableMelting` 以外の時刻を揃えた条件を追加します。

振動はNone、MeltSynchronous、MeltDelayed、ThroughoutTrialの4種類。ThroughoutTrialは**準備〜観察の刺激系列全体**で、前後のドリフト計測・質問・休憩中は停止します。連続条件は総刺激時間も変わるため、時間差だけの比較ではありません。実機出力の強さ、装着、伝達遅延は別途測定します。

`Application.persistentDataPath/VirtualHandLogs` に `.study.json`（条件順・設定・全回答・理由・質問）と `.study.csv`（1試行1行）、各刺激試行CSV/JSON、brush軌跡、振動送信キューのログを保存します。被験者は匿名コードを用います。PC操作で作ったrunは `Desktop simulation` と記録され、実験参加者の計測とは区別されます。HMD上の光出力・皮膚上の接触や振動到達時刻は計測していません。

## ESP32

Windows USB出力用の任意ブリッジです。[ESP32HapticController](https://github.com/TaiyouSun490/ESP32HapticController) のUnity用 `Esp32VibrationController/Runtime` を別途導入します。標準Assembly-CSharpへの導入を想定し、リフレクション用link.xmlを同梱しています。独自asmdefへ入れる場合はそのアセンブリのクライアント型をlink.xmlで保持してください。

既定COM4、CH0–3。接続時はミュート。通信はワーカースレッドで実行し、各フレームのUSB待ちを避けます。デバイス未導入でもVibration=Noneでコンパイル・実行可能です。USBが物理的に断線した場合、停止コマンドの機器到達は保証できません。

## 検証範囲

`Tools > Avatar Experiments > Virtual Hand > Run isolated Play Mode verification` は合成入力で計測計算、順序、配置と遅延の合成、4振動条件、停止、保存を検証します。結果は `Library/VirtualHandVerification.txt`。人での錯覚成立、コントローラー先端の実測精度、測定法間の同等性はこのテストでは確認できません。
